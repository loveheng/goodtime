# 拾光（shiguang）——MCP 日程 app 设计

> 结论先行：拾光是一个**本地持有的日程台账 + MCP 服务 + 确认 UI**，日程生成的推理全部交给桌面 AI 客户端经 MCP 完成（零端侧 LLM）。架构复刻拾贝（goodshare）已验证的 Human-AI 对称性模式。**用户输入的是概念，日程装的是行动**——两者之间的细化管道是本产品最核心的工作面。

## 1. 一句话定位与粒度定律

**拾光管「还没定但想做的事」，系统日历管「已经定了的事」。** app 内中央 agent 为确定性管家（无 LLM），推理大脑在桌面 AI 客户端。

> **粒度定律（本设计第一原则）**：用户输入的是概念，日程装的是行动。两者之间隔着一整条细化管道（拆解+澄清），这条管道就是这个 app 的核心工作面。

四级粒度阶梯：

```
概念   「想去云南玩」「有个考试」            ← 快记捕获，零细节，落清单
  ↓ 拆解（AI）
任务   「订往返机票」「练和弦」              ← 有方向有时长感，还不可排
  ↓ 细化（AI + 澄清问答）
行动   「练 C↔G 和弦转换 20 分钟」          ← 一次能做完、时长明确、动词开头
  ↓ 排程（AI propose / 人直接放）
块     周三 19:00–19:20 + 行动 label        ← 时间+行动，日程表的原子
```

## 2. 为什么不只是一个 AI 工作流（对「直接用 ZCode 不就行了」的回答）

| 需求 | 只用 AI 客户端 | AI 客户端 + 拾光 |
|---|---|---|
| 三月说的「想学吉他」，十月还在吗 | 沉在对话历史里，靠运气 | `list_plans` 一查即中 |
| 数百条计划与执行记录 | AI「记得」，无法验证，必然幻觉 | sqflite 台账，机械可查可聚合 |
| 排程冲突校验 | AI 自己查自己 | 命令层硬校验，非法写入直接拒 |
| 完成率/Q2 占比/粒度纠偏 | 无数据可聚合 | `get_history` 返回真数据 |
| 手机上 30 秒记一个念头 | 先开电脑 | 快记条，无 AI 参与 |
| 早上 7 点看今天干什么 | 打开 AI 问一轮 | 打开 app，勾选即完成 |
| 换客户端/换模型/新会话 | 记忆重置 | 台账+playbook 在，任何 AI 三分钟接管 |

**对话是易逝的，台账是持久的；AI 负责推理，不负责记忆。** AI 无状态不是妥协而是设计：正因 app 独立持有全部状态，AI 才是可替换的。

## 3. 核心循环与三方职责契约

```mermaid
flowchart LR
  A[捕获 快记条 零细节] --> B[消化 澄清+拆解 AI对话]
  B --> C[排程 propose/人直接放]
  C --> D[执行 今天页 勾选]
  D --> E[复盘 get_history 聚合]
  E -->|修正估计与粒度| B
  C -->|被排期=升格| B
```

三方职责（Human-AI 对称性，拾贝同款）：

- **App = 台账 + 裁判**：存储、状态机、机械校验（重叠/作息边界/plan 存在性）。永不判断「排得合不合理」。
- **AI = 排程师**：读数据、权衡、写回提案；非法写入被拒并收到原因。
- **人 = 终审**：确认/否决/微调；否决原因可选，AI 下轮参考。

**校验刻度故意不对称**：人可以任性（手动块允许重叠、越界，app 橙色提示但放行）；AI 必须讲理（`propose_schedule` 撞任何重叠/越界整单拒绝并返回原因）。错误提示对人是反馈、对 AI 是重试信号。

**和平条款**：`propose_schedule` 整天写入只替换 AI 自己的块；human 块与 pinned 块对 AI 而言=当天固定占用，必须绕行。AI 要动用户的块走 `adjust_blocks` 显式指定 id。

**反压迫条款（泰勒制防线，2026-10-05 拍板）**：**App 负责无偏见的事实统计，AI 负责带理由的温和提案，人掌握显式规则与一键赦免权。** AI 永不排满时间表（呼吸律见 §7）；提案必须携带决策理由；用户偏好写在明处（`settings.user_rules`）而非被「猜」；历史坏账有一键赦免出口（Clean Slate，见 §8）。

## 4. 数据模型（三表）

### plans（清单条目 = 唯一的「家」）

| 字段 | 说明 |
|---|---|
| `title` | 用户随手打的原始标题，原样保留（清单显示用） |
| `spec` | **精确无歧义描述**（AI 维护的唯一权威陈述），可空 |
| `notes` | 已敲定细节的沉淀（自由文本，AI 回写） |
| `open_items` | 未决问题 JSON 数组 `[{question, answer?}]` |
| `min_viable_action` | 降级行动描述（「哪怕只读 1 页」），澄清/拆解时由 AI 顺带产出；spark 模式的执行依据（六轮评审拍板） |
| `energy_level` | `deep`（深度专注）/ `light`（轻松琐事），默认 light——快记零负担（七轮评审拍板） |
| `tool_required` | `desk`（需电脑桌前）/ `anywhere`（手机即可），默认 anywhere |
| `reward_spec` | 犒赏锚点（「潮汕牛肉火锅」「开心果拿铁」），澄清管道对高阻力计划收尾收集；兑现时生成庆祝块（九轮评审拍板） |
| `importance` | 布尔，手动一击（快记条旁一颗星），AI 可建议改 |
| `deadline` | 可空截止日；临近自动升「紧急」（派生） |
| `estimate` | 预估时长（概念态粗估，细化后修正） |
| `parent_id` | 父计划，可空，**放开多级**（政策建议深度 ≤3） |
| `version` | 乐观锁 |

### fixed_slots（固定占用 = 约束，不是愿望）

星期几集合 + 起止 + 名称；支持工作日/周末两套模板并存。**跨午夜块（睡眠 23:30–07:30）按开始日归属，不拆段**；校验查「当天开始的固定占用 + 前一天溢出段」。**空表合法**（自由职业预设）。

### schedule_blocks（日程块实例）

| 字段 | 说明 |
|---|---|
| `date` + `start/end` | **必须有起止**（不支持弹性块，拍板）；跨午夜同 fixed_slots 规则 |
| `plan_id` | 可空——用户直接在日程表放的孤立块不欠清单交代 |
| `label` | 块自己的行动描述（动词开头），可空，缺省回落 plan 标题 |
| `source` | `human` / `ai`——和平条款的依据 |
| `pinned` | 钉住标志：AI 创建的无 plan 块（火车/面试/航班）默认 pinned；用户可钉任何块 |
| `status` | `proposed → confirmed → done / skipped / missed / archived / melted`（过期未确认日切自动 missed，可补勾带「补记」标；archived=断流静默保护的中性归档态，不计入复盘聚合；**melted=水流溢出/熔断的中性融化态**——被现实挤出时间窗的 AI 块无痕蒸发回愿望池，绝不显红；**仅因物理位移触发，绝不因「没打卡」触发**，后者走日切 missed→宽容视窗） |
| `postpone_count` | 顺延计数（顺延=移动原块保身份，+1；≥3 打「需人工决策」标） |
| `execution_quality` | `full` / `spark`——spark=打折执行（计划 1h 只做 5min 启动动作，执行内容取 plan.min_viable_action），承认启动价值、计入有效推进不扣分（六轮评审：自五轮 is_degraded 演进统一） |
| `is_day_spark` | **当日黄金火种标志**，每作息日至多一个（AI propose 指定当天最重要的那件事）；火种 done/spark = 当天秩序判定为健康——「只推进这一件事就算胜利」（六轮评审拍板） |
| `is_celebration` | **庆祝块标志**（香槟金渲染），享有最高豁免权：过期绝不 missed（日切静默 archived 淡出）、水流模型最后才可动且仅限全局熔断、兑现计入能量回血。九轮评审：以 bool 替代其 block_type 枚举方案（shield 已定派生不入库，枚举无意义） |
| `version` | 乐观锁 |

**车上 5 小时想利用 → 分解，不嵌套**：火车块可被替换为「赶车/阅读/处理邮件」若干段，坐着能干的事就是普通 plans，零新机制（明确否决嵌套子块结构）。

**系统日历只读投影（七轮评审拍板）**：经 `device_calendar`（拾贝 PRD V3 同款插件，经验同源）读取当天/明天的系统日历事件，**不入 SQLite，纯内存投影**为 `source='human'、pinned` 的阻隔块——校验引擎视其为不可穿透硬墙，AI 排程自动绕行；用户在外部日历（飞书/Outlook/Google）被拉会时拾光自动感知，免除双重录入。重启/日变更高即重读，零存储污染；日权限申请失败→静默降级为无投影（不影响其余功能）。

### 派生状态清单（能算出来的绝不存）

| 派生状态 | 定义 |
|---|---|
| 当下要做的 | 有未来排期块（confirmed/proposed）的 plan |
| 待安排 | 没有任何排期块的 plan |
| 紧急 | 有 deadline 且距今 ≤ 阈值（默认 3 天） |
| 明确态（readiness） | spec 非空且精确 **且** open_items 为空 |
| 清单三分区 | 今天 / 当下推进中 / 待安排——同一份数据的分组视图 |

## 5. 四象限政策

两字段笛卡尔积，纯派生：`importance`（手动）× `urgency`（派生自 deadline）。

| 象限 | AI 排程政策 |
|---|---|
| 重要+紧急 | 优先落位，今天/明天必须见到块 |
| **重要+不紧急（黄金象限）** | 主动圈地：AI 每天给这类事预留空间（配合「单日新增排量上限」反向使用） |
| 不重要+紧急 | 见缝插针塞间隙；治理时建议放弃 |
| 不重要+不紧急 | 愿望池，有富余才排；「帮我清一下清单」的主要对象 |

捕获默认落「不重要+不紧急」——所有事从愿望池出生，**被排期就是升格**。四象限政策写进 MCP `instructions`，不新增工具。复盘聚合含**分象限完成率**，Q2 完成率 = 本产品对用户生活的核心价值度量。可选设置「Q2 每日保底时长」记档不实现。

## 6. MCP 工具面（九个）

| 工具 | 说明 |
|---|---|
| `list_plans` / `add_plan` / `update_plan` | 愿望 CRUD；update 为**字段级 patch + 乐观锁 version**。list **默认只返回未完成叶子+就绪态节点**（归档/已完成/冷数据不拉），过滤参数显式可放开——防上下文膨胀 |
| `get_settings` / `update_settings` | 作息边界、最小块粒度、单日新增排量上限、**单日执行耐受阈值**、**`user_rules`（显式偏好文本，如「周五晚上不排深度工作」，AI 经 update_settings 维护）**；get 返回体含 fixed_slots 与当前日期 |
| `update_fixed_slots` | 批量原子替换（沿用整单校验模式） |
| `propose_schedule` | **按天整表原子写**（拍板 2026-10-05）：全部合法才落库，否则逐条返回原因。机械校验清单：重叠/作息边界/plan 存在性/**填充率红线（AI 块总时长 ≤ 当日可用时间 60%，默认可调——留白是吸收意外的护城河，五轮评审拍板）**/**呼吸律缓冲（>45min 块后 15min 空白，与填充率同批升为命令层机械校验）**。周维度只做 Q2 空间预留，每天晨间一次 propose。**被拒时返回体附 `available_free_windows`**（当日剩余连续空闲窗口），AI 填空不盲猜；**返回体含 `protection_manifesto`**（shielded_free_minutes / slack_ratio / suppressed_tasks_count / narrative——命令层按与校验同源的规则常量计算，护航功劳可量化，八轮评审拍板）；playbook 配套：propose 前必须先 `get_schedule` 读当天 human/pinned 分布，先读后排（防排程死锁） |
| `adjust_blocks` | **建/挪/缩/删**块，按 id；AI 放单日行程（火车）的入口 |
| `get_schedule` | 无参返回今天+明天（**服务端供日期**，AI 不自己算「下周三」）；可选 `days`（≤3）拉长视窗，返回体附**三日容量水位线**（空闲=作息−固定占用−投影日历，纯几何计算）——按天排程的远视补丁，防猝不及防的密集日程 |
| `get_history` | 近 N 天（默认 14）完成聚合 + **三组物理校准指标**（2026-10-05 拍板，纯 SQL 聚合、无模型、无偏见）：①分象限完成率；②**时长膨胀系数**（done 块 Σ实际时长/Σ原始估算，如 1.35=习惯性低估 35%）；③**时段完成率**（早/中/晚分区 done 率）；④**耐受阈值**（单日执行超此分钟数则次日 missed 率激增，检测不出回退默认=单日新增排量上限）。**主指标=深潜净值**（核心=Q2 象限沉浸的绝对分钟数，spark 计入；彻底抛弃完成百分比——勾 4 个琐事的 80% 完成率可能是「高效的逃避」，六轮评审拍板；叙事模板：「今日遭遇 N 次突发扰动，成功保全 X 分钟核心火种」）；附**能量回血**（庆祝兑现率与分钟数）作为正向平衡指标（九轮评审）；完成率/missed 率降为 AI 内部诊断指标，不面向用户展示。**恒为聚合体，永不返回明细行**（硬约束，防上下文膨胀） |

校验铁律：settings 未初始化（或 fixed_slots 与作息矛盾）时 `propose_schedule` **整单硬拒**，绝不静默按 24h 空闲排。

**乐观锁冲突的返回契约（防「后台思考 vs 顺手改」踩踏）**：`update_plan` 等写工具报 version 冲突时，错误体**直接携带最新快照**（继承 goodshare「CommandResult 回最新快照」纪律）——AI 无需重拉 `list_plans`，当场在快照上合并自己的修改重试；重试语义写进工具返回说明与 playbook。

## 7. 行为层三层承载（半个产品）

| 层 | 载体 | 内容 | 何时进 AI |
|---|---|---|---|
| 政策精华 | MCP `instructions` | 只排叶子、排前须明确态、human/pinned 不可动 | 每次 initialize，必读 |
| 操作 SOP | **MCP prompts**（实装 prompts/list+call） | 「排程」「澄清」「拆解」「清单治理」四流程 | 按需取用，任何 MCP 客户端 |
| 完整 playbook | **SKILL.md** 随仓库分发 | 全部政策 + spec 写作规范 + few-shot 案例 + 反模式 | ZCode 等装进 client，触发词自动加载 |

skill 与 prompts 内容同源（仓库同一批 markdown），不分叉。playbook 大纲：`clarify.md`（open_items 问答次序、spec 写作规范）/ `decompose.md`（粒度阶梯、叶子=行动）/ `schedule.md`（读史→象限权衡→Q2 圈地→propose、被拒修正循环）/ `govern.md`（清淤判据、粒度纠偏）。

**AI 政策**：不排概念（只排叶子，父计划被要求排期先下钻/先拆解）；块 label 用行动语言；时长估不出=澄清项进 open_items，不瞎猜；**排程前必须到达明确态**；有未决 open_items 先澄清再排（软政策，允许先排已确定子任务）。

**澄清收敛阈值（防 open_items 死循环）**：单轮最多追问 2–3 个问题，按「先时间后细节」排序；用户连续两次回答「不知道/不想定」的项，AI 不得继续追问——提取**最小可执行单元**强行推进到明确态，未决内容记入 notes 备注「待定」，不再阻塞排程。澄清是管道，不是审讯。

**最小澄清原则（防审讯疲劳）**：估算 ≤30 分钟或性质平凡（购物/琐事类）的任务**免除澄清**，直接生成叶子行动——澄清的价值必须大于直接排的成本。琐事配得到的是一次被排上日程，不是三连问。

**呼吸律与客观校准（防泰勒制排满，2026-10-05 拍板）**：
- **强制缓冲**：单块 >45min 后必须留 ≥15min 绝对空白（现实延误的缓冲垫）——**五轮评审升级为命令层机械校验**（与填充率红线同批），不再是 playbook 软约束
- **时长乘数补正**：按膨胀系数放大圈地——估 40min × 1.35 ≈ 55min，冗余留给意外
- **user_rules 优先**：`settings.user_rules` 的显式规则（「周五晚上不排深度工作」）优先级高于统计推断——规矩写在明处，不黑盒猜习惯
- **提案附理由**：每份排程方案必须携带决策解释（「高数复习排上午 09:30，因为数据显示你上午完成率 82%；16 点后只排琐事，留 45 分钟空白缓冲」）

**断流复苏 SOP（recovery_mode，2026-10-05 拍板）**：检测到断流（连续 3 个作息日无打卡/确认交互，或 missed 累计 ≥5）时：①**禁止复盘旧账**——不问「为什么这三天没做」，不罗列堆积清单；②主动发**一键赦免**提案（「建议把过去未竟事项全部退回愿望池，今天只聚焦一件最重要的事」，AI 提案、人确认，不单方面动块）；③**极简重启**——当天只 propose 1–2 个高价值核心块，其余留白，重建节奏感。

**锚点优先于钟表（五轮评审，政策采纳/结构婉拒）**：AI 选时段以生活事件为参照，而非纯钟表——高阻力 Q2 挂晨间锚点（起床/早咖啡）后、低阻力琐事挂睡前锚点、硬日程（fixed_slots）结束后 +20min 插短任务、两固定事件间空白标注「午后窗口（约 2h）」。但**产出仍是精确起止块**（守住「必须有起止」拍板）。「底层弹性泡泡」结构**明确婉拒**：它会给 propose 校验、管家日切、BlockRenderer 制造第二时间真相；体感弹性已由顺延微调/宽容打卡/沉浸顺延/熔断键/降级执行完整提供。

**减震器原则（schedule.md 卷首，五轮评审）**：「AI 是用户的减震器，不是工头。检测到日程重叠或时间紧张时，第一反应是**削减任务总量、扩大留白**，而不是把事情塞进更紧密的缝隙。」

**骨架与肌肉分层（六轮评审，2026-10-05 拍板）**：宏观骨架=作息底线+fixed_slots+human/pinned 块+**当日黄金火种**（绝对刚性）；微观肌肉=其余 AI 块（流体，可随时被打乱、推迟、压缩、融化）。**秩序健康判定：骨架没散即健康**——作息没崩、火种 done/spark，当天肌肉全乱也不算失败。传统工具死于把人当确定性状态机，而现实是随机扰动系统。

**水流模型（替代多米诺骨牌，六轮评审拍板）**：现实扰动落下（如突发加班 human 块）→ 命令层确定性重算当日，三级阻尼：①先淹没留白（填充率红线的 40% 护城河）；②仍不够 → 后序 AI 块自动降级 spark（压为 min_viable_action 核心动作）；③仍装不下 → 非核心块 **melted 蒸发回池**。融化牺牲顺序（九轮评审补）：非核心 AI 块最先 → 黄金火种靠后（压 spark 优先于融化）→ **庆祝块豁免**（仅用户触发全局熔断才可动）。触发于人工块加入/顺延微调造成物理挤压时；调整结果在今日页以中性摘要呈现（「下午因加班：B 缩为火种、C 已回池」）且**可一键撤销**——自动化不等于不可审计。

**MCP 第一定律（进 instructions，六轮评审）**：「AI 永远假设用户的生活处于布朗运动中。排程不是为了占满时间，而是为了在混乱的洪流中，用最低的认知摩擦，为用户捞起一颗珍珠。」

**启动第一步（Landing Gear，七轮评审）**：AI 细化行动时，必须在 `plan.notes` **首行**沉淀一句可立即执行的启动第一步（「打开 PDF 第 45 页第 3 题」「打开终端跑 npm test」）——行动之前的 60 秒是认知摩擦最大的时段，把启动阻力从「想我要干嘛」降到「执行眼前这句话」。零 schema 变更：notes 首行是 playbook 约定，块卡片点开浮层直显 spec+notes。

**精力匹配政策（七轮评审，软政策）**：`deep` 任务放精力高位区（依据 get_history 时段完成率）、`desk` 任务不排入无电脑时段；标签只进 playbook 推理，不做命令层硬校验。

**三日态势句（七轮评审）**：晨间 propose 输出必须附宏观态势感知（「注意：明天全天培训，可用时间仅剩 1.5 小时。建议今天在黄金火种之外，把复习资料提前下载好」）。

**护航式提案叙事（八轮评审，2026-10-05 拍板）**：提案交付绝不开工头腔（「今天有以下 5 项安排，请准时开始」），必须**护航式邀功**——显式计算替用户拒绝了什么、守住了什么：「愿望池堆了 6 件，我帮你拦截了 4 件；守住了傍晚 3 小时绝对自由，并在高数后锁定 45 分钟缓冲。今天只推进 1.5 小时，你的底线就彻底守住了。」用户质疑「怎么只排这么点」时，AI 援引客观数据防愧疚背书：「数据显示你的单日耐受阈值是 210 分钟，超额安排会导致随后两天 missed 率飙升——这 3 小时留白是为了你明天不断流。」

**庆祝体系（九轮评审，2026-10-05 拍板）**——多巴胺回路闭环：完成后的情绪确认与下一个待办同样重要。

- **三级阶梯**：①**微观战壕回血**——火种块后紧随 20–30min 庆祝块（甜点/散步/听播客），propose 时 AI 必排；②**稳态守线奖赏**——连续 3 个作息日保全黄金火种，AI 主动圈「功勋自由时段」（如周五晚 2 小时）；③**宏观战役胜典**——整条 plan 全叶子完成（管家巡检打标），兑现 reward_spec 预排半天专属块
- **clarify 收尾**：高阻力计划（importance 且预估总耗时 ≥180min）澄清的最后一个问题固定为「这仗打完，准备怎么犒赏自己？」→ 答案落 `reward_spec`；decompose 的收尾叶子=兑现奖励（动词开头、有时长），不是生硬的「复盘总结」
- **叙事**：庆祝在提案中是成果汇报的一部分——「重点是我 15:30 紧接着排了你念叨的拿铁时间。打完硬仗就该有战利品，这个块不可侵占，喝完咖啡今天主线就彻底守住了」
- **豁免纪律**：未兑现的 reward_spec **永不催促**，仅自然时机温和重提；庆祝块缺席零心理负债——庆祝是盟友碰杯，不是新 KPI

**中性语言与净产出复盘（五轮评审拍板）**：严禁负罪感文案（「您已落后进度 40%」「今日任务未达成」），界面只陈述中性事实（「今天吸收了 2 个意外事件，推进了 1 项核心行动」）；missed 数据层照记（耐受阈值/断流检测依赖），变的只是叙事与权重——传统工具死于把生活脱轨记成失败账单，拾光把「崩溃与偏离」当正常业务流：混乱才是主流程，按部就班是小概率奇迹。

**验收**：金样本评审循环——「有个考试」案例固化为固定输入，每次改 playbook 人工跑一遍，评审追问次序与 spec 产出；样本积累后扩成小集合。

```
捕获：有个考试（title）
AI 问：什么考试→期末考；什么时候→11-20；考哪几科→高数、英语、数据结构
update_plan：spec="2026-11-20 期末考试，共 3 科：高等数学、大学英语、
  数据结构；地点教学楼（待确认）"，open_items=["考试地点在哪栋楼？"]
派生：deadline 11-20 临近自动升紧急
拆解：高数复习 / 英语复习 / 数据结构复习（子计划，可再细化成行动块）
排程：考前一周 propose_schedule，块 label 精确到「高数：第三章极限习题」
```

## 8. Housekeeper 中央管家（确定性，无 LLM）

复用拾贝前台服务基建，只做时间驱动的状态迁移与漂移浮出，不做判断：

```
├─ 日切扫描：过期未勾块 → missed（可补勾）；过期 proposed → 作废
│   ※ 日切触发点 = wake_time 而非物理 00:00（防夜猫子惩罚感）：
│     凌晨收尾的工作仍算「昨天」；「作息日」概念贯穿管家日切、
│     复盘聚合、propose 默认目标日——全部用作息日而非日历日
├─ 顺延记账：维护 postpone_count，≥3 打「需人工决策」标
├─ 晨间聚合：生成「昨日遗留 + 今日计划」digest（确定性视图）
│   ※ 孤儿概念分阶段处置（四轮评审修正二轮拍板，防晨间道德审判）：
│     新孤儿（<7 天）进 digest，AI 开工**主动消化**（AI 拆解，非质询
│     用户）；超 7 天未动 → 自动静默**冷藏**（派生态=孤儿+updated_at
│     超龄，不新增存储），退出 digest 不催促；仅显式「帮我整理清单」
│     时翻出冷藏池，且默认建议批量丢弃而非逐一拆解——快记条必须是
│     轻盈的灵感捕获网，永远不许变成债务账本
├─ 提醒触发（V1.5 第一优先级）：块开始前 N 分钟本地通知
├─ 数据巡检：open_items 超龄、spec 长期空 → 打「需澄清」标
└─ 断流静默保护（Clean Slate，2026-10-05 拍板）：连续 3 个作息日
    无打卡/确认交互 或 missed 累计 ≥5 → 停止标记红色 missed，改中性
    archived 且不计入复盘聚合；恢复交互即退出保护。防「破罐破摔」
    的负罪感螺旋，历史坏账由 AI recovery SOP + 一键赦免出口化解
```

「需要判断」的部分归桌面 AI——管家把问题浮出来，AI 负责谈。

晨间对齐入口：app 今日页顶部固定「昨日遗留」区 + AI 排程 SOP 第一步强制读遗留（两边同一份数据）。

## 9. 首启引导（3 步，第一步不可跳）

1. **作息边界**（必填）：起床/睡觉
2. **一周节奏**（可跳过）：工作日/周末两套固定占用模板，预设（上班族/学生/**自由职业**）一键生成可改；自由职业=留空直接过，「没有固定安排是完全正常的」
3. **排程偏好**（可跳过）：最小块粒度、单日新增排量上限（休息权的模型支撑）

引导的本质=给 fixed_slots 和 settings 播种。自由职业者的「工作」走 plans/blocks（要被安排的事），与「学吉他」同等对待。

## 10. UI 结构

底部两 tab：**日程**（默认，日视图；点空槽创建→「新建事项」或「从清单选」提名）｜**清单**（三分区 + 条目「排期」快捷动作）。快记条两 tab 顶部常驻（输入框 + 一颗星 + 可选截止日，捕获永远零细节）。设置右上角进（含 MCP 服务开关/token，拾贝 mcp_page 改）。

日程表块显示自己的 label；来自清单的块带 📋 角标。确认页「确认/否决/改时间」三键 MVP，外加**单块「往后顺延 30 分钟」快捷微调**——级联顺延同日后续 **AI 块**（human 块原地不动，撞了仅提示），化解现实时间漂移的多米诺效应（维护摩擦必须小于执行阻力，否则用户弃用）。**拖拽 V1.5（已拍板，见 §11）**。

**体验防线（四轮评审收编，2026-10-05）**：

- **网络配对**：MCP 设置页=状态指示灯 + 当前局域网 IP + 一键唤醒；stdio-bridge 增加 mDNS/Zeroconf 自动发现（`shiguang.local`，Android 侧 NSD 广播），手动填 IP 仅作兜底——IP 漂移和后台休眠造成的「Connection Refused」必须在用户修网络之前被消灭，排程热情不能耗在前 3 分钟的报错里
- **确认分级（防批量盲签）**：提案确认页**禁止平铺 6–8 个块**——顶部突出**当日黄金火种**（为什么排在这、预留了多少缓冲），Routine 与琐事折叠为「其余 N 项日常推进」；把用户的审查精力留给真正的决策点，否则「人是终审」会被盲签架空
- **心流保护**：打卡永不实时强制——宽容视窗（块结束后至次日 wake_time 均可勾，含晚间一键批量补勾）；进行中块提供「沉浸中，别理我」=复用顺延微调（+30min 级联 AI 块），不许闹钟把用户从心流里拽出来伺候打卡机
- **现实熔断键**：突发危机（临时会议/孩子发烧）时日程页一键全局动作——「清空今日/下午 AI 块」（受影响块整体撤回、plan 自然回落待安排派生态、**无负罪感标记**）或「暂缓 2 小时」（级联顺延）；human 块永不动。走命令层原子执行，AI 侧同效动作走 adjust_blocks。五轮评审重申其定位：**熔断优先于微调**——重大变故时不该让用户精细挪 5 个块
- **降级入口**：今天页提供「今天状态差，只做启动动作」（单块 spark，执行内容取 plan.min_viable_action，见 §4）；全 app 文案遵守中性语言禁令（见 §7），只陈述事实不审判
- **启动脚手架**：块卡片一键浮层直显 spec+notes（首行=启动第一步）；从「看到日程」到「开始执行」的 60 秒断层在此弥合
- **即兴逆向记账**：今日页空白时段点按→「刚才做了什么」→挂已有 plan 或孤立 label，落库 confirmed+done 并计入深潜净值。**记账走事实通道，豁免排程校验**（填充率/重叠）——记录现实不是制定计划，不把「严格按 AI 排程」当唯一美德，凡是真实专注全部承认
- **换乘开关**：某块因疲劳无法执行时点「换一个」——原地换入待安排池中时长相近的 `light` 琐事（app 命令层动作，不经 MCP），化解精力死锁
- **投影块**：日视图中系统日历事件以灰底+外部来源图标显示（BlockRenderer 统一处理）

**护航呈现（八轮评审，2026-10-05 拍板）**——休息从「空虚缺席」转为「一级保护资产」：

- **休息显性确权**：留白不渲染为无主虚空——呼吸律缓冲渲染为淡绿「🛡️ 能量补给带（已保护 45 分钟）」，填充率红线的留白渲染为「🍃 自由流动区（已达今日精力安全线）」。**保护区一律派生渲染、不入库**（`block_type` 列婉拒：保护区由与校验同源的规则常量几何算出，存储会造出第二真相——与弹性泡泡同理由）；保护区对水流模型不可侵占
- **双轨仪表盘**：今日页顶部 `🔥 黄金火种 1 项 ｜ 🛡️ 自由保护时间 4.5h`——保护时长与推进任务并列为核心交付指标，让用户看见 App 替自己抢下的领地
- **安全线徽章**：火种 done/spark 的瞬间点亮「今日安全线已达成」，文案切换为「核心底线已保全，剩余时间自由处置——做是额外奖赏，不做零心理负债」（六轮秩序健康判定的 UI 时刻）
- **放工守卫**：sleep_time 前 2 小时进入休眠守卫态——隐藏未排期清单浏览与推进提示，界面转静默视图；**快记条永不关门**（夜间恰是念头高发期，捕获零门槛不因放工打折，新念头落池待晨间消化——对评审方案的显式修正）
- **庆祝块**：香槟金徽章渲染（BlockRenderer），完成勾选瞬间轻量微动效；**绝不显红**——过期即静默淡出，视觉上与普通块的失败态彻底隔离（九轮评审）

**跨午夜的显示层独立（数据层/渲染层分离）**：归属规则只在数据层执行（按开始日）；日视图渲染跨午夜块（截断/溢出/次日回显）统一收敛到独立的 **BlockRenderer** 组件处理跨天映射，禁止散落在各页面的布局代码里。
