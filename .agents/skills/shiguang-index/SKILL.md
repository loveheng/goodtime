# shiguang · 功能落点索引（规约）

> **索引数据 = `docs/project/index.md`**（索引数据住 docs/project/，skill 只放规约——goodhub 既定结构原则，拾光对齐）。索引机制（表格式规范、增量登记纪律）见全局 `project-index` skill，本文件不复制其正文。

## 1. 索引构成

`docs/project/index.md` 登记以下内容，各有专属维护协议：

| 块 | 内容 | 何时登记 / 更新 |
|---|---|---|
| **代码落点** | 功能 → 代码落点 + 备注（红线 / 设计稿 / 注入位等指针） | 新功能落地、搬迁、改名后同轮登记 |
| **跨域隐式契约** | 机器查不出的跨域约定（文案词汇表 ↔ 界面字符串、SettingsKeys ↔ propose 判据等） | 发现新隐式契约时登记；能用测试/护栏守护的优先加护栏，护栏建成即从本块移除 |
| **跨仓复用源** | 拾贝 goodshare 领料指针 | 复用清单变化时（SSOT = schedule-app.md §12，本块只留指针） |

> **文档明细不入索引**：全量文档清单唯一事实源 = `docs/README.md`（docs-lint 双向覆盖校验兜底），本索引不复制（防双源）；文档域级变迁（新增域/拆分/合并/整体迁移）才按 docs-spec §2 同步本 skill 索引构成。

> 架构债暂无活跃项：出现跨域违例需挂账时，仿照 goodhub 模式在本文件增设「架构债与依赖违例登记」活跃表（先登记再动手，清零即结项归档），并在本 skill §2 补结项归档纪律。

## 2. 登记纪律

- **增量登记，禁止一次性铺满**：表随实现长出来，不为「完整」预写空泛行。
- **一行一功能**：功能名可读（勿写任务号）；落点精确到文件（`lib/...`、`docs/...` 仓库相对路径，禁绝对路径）；备注只放定位后必读的指针（测试、SSOT 文档、注入位、红线）。
- **禁写施工过程**：日期、切片/步号、里程碑交付记录、重构心路一律不进备注——过程事实归 Git log 与 `context/epics/`；备注单格以「指针 + 一句话红线」为上限。
- **禁留路径墓碑**：路径已不存在时直接删除该指针（Git 历史可溯），不写「XX 已不存在，勿再引用」类正文。
- **禁写易腐数字**：即时行数、计数、测试通过数等每次提交都会漂移的数字不入表。
- **失效落点即修**：发现表中路径不存在 / 语义过期，同轮修正或删除，不留「待对账」。
- **可推导的不维护**：路径/命名/脚本现场可 derive 的不登记；禁止为收集目的给文件新增元数据字段，禁止写类清单/文件触点清单。

## 3. 维护协议

- **用法**：先查 `docs/project/index.md` 定位领域落点，定位不到才全量 grep——展开的类清单只用于当前任务，禁止写回本表。
- **文档明细不进本索引**：全量文档清单唯一事实源 = `docs/README.md`；仅域级变迁按 docs-spec §2 同步（`docs/README.md` + shiguang-docs 域路由表 + 本 skill 索引构成）。
- **设计变更回 SSOT**：设计变更回 `docs/design/schedule-app.md` §11 拍板台账留痕，索引不复制设计语义。
- **命令速查不进本索引**：命令与环境事实源 = shiguang-workflow skill。
- **索引体检（防慢性腐化）**：索引腐化是单次登记都不违规、累积后显形的过程——epic 收尾（`::done`）或重大重构后对账一次：① 落点路径存在性抽查；② 隐式契约块是否已有护栏可移除。发现漂移同轮修正。
